# 被开发拉黑 3 次后，我做了一套让业务同事自助取数的系统

> **一句话**：上传 Excel，自动从数据库查数据，结果写回原 Excel。零 SQL、零开发、零等待。
> **项目地址**：`excel-database-query`（GitHub 搜不到的话评论区留邮箱我发链接）

---

## 一、三次"被拉黑"的故事

第一次被拉黑，是在我又发"在吗？能帮我导个表吗"之后的第 4 个小时。

对方是研发小李。我们关系本来不错，但那一周我已经问他 3 次了：
- "华东区上个月销售数据能帮我跑一下吗？"
- "XX 表能不能加个客户的筛选？"
- "我想要 Excel 格式的，能发我邮箱吗？"

他没回我消息。我以为是忙，第二天看到他在群里说："**求求各位业务同学，提数的事能不能攒一周一次问？**"

我默默退出了聊天窗口。

---

第二次被拉黑，是凌晨 2 点。

那天老板要一份临时数据，我自己学着写 SQL，写了 3 小时没跑通。
凌晨 2 点，我给后端同事老王发消息："哥，帮我看看这个 SQL 是不是哪里写错了？"

他 5 分钟后回了我一句：

> "睡了，明早再说。"

我盯着屏幕坐了半小时。**既委屈，又理解**。

---

第三次被拉黑，是开发同事直接在群里 @我：

> "哥，真不是不愿意帮，主要是这事本来就该有个系统解决。我们再这么互相消耗，谁也干不好自己的活。"

那句话像一记重锤。

那天晚上，我失眠了。**不是生气，是忽然意识到一件事——**

> 我们公司每个月有 **上百次**"帮我导个表"的需求。
> 每个需求平均要研发花 **30-60 分钟**。
> 这些时间，本可以拿来做更有价值的事。

---

## 二、我们做了个决定

三个月后，我（业务）+ 一位研发同事 + 一位 DBA，凑了个三人小组。

目标很明确：
> **让业务同事自己取数，把研发从"提数机器"里解放出来。**

我们不重复造轮子。市面上 BI 工具很多，但都太重——要学、要配、要权限。我们想要的是：

> **业务同事已经会用 Excel，那解决方案就应该"长得像 Excel"。**

三个月后，第一个版本上线。我们给它起名叫 **Excel Database Query**。

---

## 三、它长什么样？三步出第一份数据

### Step 1：管理员配查询选项（开发做一次）
- 选个数据库连接（MySQL / PostgreSQL / SQL Server / MariaDB 都行）
- 写个 SQL 模板（支持 Jinja2 动态生成）
- 配个查询选项（"华东区销售月度报表"）
- 保存。

> 💡 SQL 模板是杀手锏。比如按月分表，可以写 `SELECT * FROM orders_{{ month }}`，系统自动展开成全年 12 张表的 UNION ALL。

### Step 2：业务同事上传 Excel
- 把要查的 Excel 拖进网页
- 系统根据文件名**智能推荐**查询选项（"华东区销售月度报表"）
- 打开「**直通模式**」——上传即查、查完即下载
- 点击"开始"

### Step 3：下载结果
- 系统自动跑查询
- 结果**写回原 Excel**，列对列、格式不乱
- 邮件直接到收件箱

> ✅ 全程**零 SQL、零开发、零等待**。

---

## 四、为什么我们觉得它"有点东西"

### 🚀 杀手锏 1：智能匹配 + 直通模式
- 不用业务同事记住"我该选哪个查询选项"
- 文件名 + 直通模式 = "扔进去就出结果"
- **真的会改变你跟开发同事的关系**（笑）

### 🚀 杀手锏 2：SQL 模板 + 大数据量分批
- Jinja2 语法，按月分表、UNION ALL 一次写好
- 几十万行数据自动分批，不会卡死
- 列名同义词模糊匹配——「客户名」「客户姓名」「CustName」都能识别

### 🚀 杀手锏 3：定时自动导出 + 邮件
- Cron 定时触发，每天/每周/每月自动跑
- 结果自动生成 Excel + 邮件通知
- 配套**流程走势图**——节点状态一眼看清

### 🧩 彩蛋：把"写代码"变成"画流程图"
- 拖拽式节点编排，业务流程自己"画"
- 条件流转（等于/包含/大于/成功失败）+ 任意节点结果引用
- 循环 + AND/OR 退出条件
- 失败即停 + 三重防重（资金场景也能用）
- 📌 这套思路我们后面会单独写一篇深度文

### 🎨 还有这些让人会心一笑的细节
- **5 套主题**（默认蓝/粉色甜美/阳光橙/暗黑/豆绿），还会**根据你的性别自动匹配**
- SSH 隧道，连生产库都不需要公网暴露
- SSE 实时推送，任务进度不用手动刷新
- 文件自动清理，磁盘永不爆
- RBAC 三级权限（菜单/按钮/数据）

### 🤖 AI 模块预告
- 我们让 **两个 AI 在公司"上班"**——一个干活的，一个挑刺的
- 执行者 Agent + 监督者 Agent 协作打分，不满意自动返工
- 还支持**插话引导**——AI 干到一半你能"插嘴"
- 详细的我下一篇专门写

## 五、谁在用？谁该用？

- 🏢 **企业数据团队**：告别提数工单，解放研发生产力
- 💸 **支付/金融团队**：可视化编排 + 失败即停 + 三重防重
- 📊 **财务/运营/市场**：自己取数，不再求人
- 👨‍💻 **DBA/后端开发**：把脏活累活交给它
- 🏫 **学校/政府/医院**：多部门多角色，统一数据出口

## 六、安全，我们是认真的

- ✅ RBAC 三级权限（菜单/按钮/数据）
- ✅ JWT 认证 + 滑块验证
- ✅ 错误信息脱敏，绝不泄露数据库结构
- ✅ 限流防刷 + URL 校验
- ✅ SSH 隧道，无需暴露生产库到公网
- ✅ 资金场景：状态/时间/运行记录三重防重

## 七、3 分钟跑起来

### 方式 A：Docker Compose（推荐）
```bash
git clone https://github.com/xxx/excel-database-query.git
cd excel-database-query
docker-compose up -d
```
访问 `http://localhost`，默认账号 `admin / admin123`。

### 方式 B：本地开发
- 后端：Python 3.10+，`cd backend && python run.py`
- 前端：Node.js 18+，`cd frontend && npm install && npm run dev`
