## 💬 评论区高频问题预案

> 这是按经验预判的 8 类高频问题，**每类都给你应答话术**（可复制粘贴）

### 🔥 第 1 类：跟 XX BI 工具有什么区别？

**预判出现概率**：⭐⭐⭐⭐⭐（必问）

**应答话术**（推荐）：
```
我们跟 BI 工具最大的差异是「学习成本」：

BI 工具：功能强，但要学、要配权限、要画图表，**轻量需求用起来很重**
我们：长得像 Excel，**业务同事已经会的操作就能用**

打个比方：
- BI 像 Excel 的高级功能（数据透视表、VBA）
- 我们像 Excel 的基础功能（拖个公式）

适合场景也不同：
- BI：复杂报表、可视化、数据分析
- 我们：临时提数、批量导出、流程自动化
```

---

### 🔥 第 2 类：数据安全吗？

**预判出现概率**：⭐⭐⭐⭐⭐（必问）

**应答话术**（推荐）：
```
安全这块我们下了挺多功夫，主要分 5 层：

1. 权限：三级 RBAC（菜单/按钮/数据），谁能看什么表都能配
2. 网络：SSH 隧道，连生产库都不需要公网暴露
3. 凭据：数据库密码加密存储，不在代码里
4. SQL：写之前会做语法校验和危险操作检测（删库这种直接拦）
5. 错误：报错信息自动脱敏，绝不泄露数据库结构

另外所有操作都有审计日志，谁查了什么、什么时候查的、查了多久，全部可追溯。

如果公司有特殊合规要求（比如等保），可以告诉我，我帮你过一下。
```

### 🔥 第 4 类：跟开发自己写 SQL 有什么区别？

**预判出现概率**：⭐⭐⭐⭐

**应答话术**（推荐）：
```
区别是「用的人」和「使用频率」：

开发写 SQL：1 次配置，1 次使用
我们的模板：1 次配置，**N 次复用**（按月分表那种场景特别明显）

具体场景对比：
| 场景 | 开发写 SQL | 我们 |
|---|---|---|
| 临时导 1 次 | 都行 | 都行 |
| 每月导 1 次 | 每月找开发 | 业务自己点 |
| 加 1 个新列 | 找开发改 | 管理员改一次 |
| 加 1 个新查询 | 找开发写 | 管理员配 |

核心是**把"重复劳动"自动化**。
开发只需要配那 5% 真正"新"的查询，80% 的活业务自己就干了。
```

### 🔥 第 5 类：上手成本怎么样？

**预判出现概率**：⭐⭐⭐⭐

**应答话术**（推荐）：
```
分两个角色看：

**业务同事**：0 成本
- 操作跟 Excel 没区别
- 第一次可能要点 3 次鼠标，第二次就会了

**管理员 / 配查询的人**：半天上手
- 会 SQL 的人 30 分钟就能配第一个查询
- 复杂的（SQL 模板 + 流程编排）可能要 1-2 天

**运维 / 部署**：1 小时
- Docker Compose 一键起
- 配置文件改数据库连接就行

我们内部上线 3 个月，**非技术同事已经能配 80% 的日常查询了**。
```

### 🔥 第 6 类：性能怎么样？大数据量能扛住吗？

**预判出现概率**：⭐⭐⭐

**应答话术**（推荐）：
```
扛得住，主要做了 3 件事：

1. **分批执行**：单次查询超过 10 万行自动分批，内存不会爆
2. **流式写入**：结果不一次性加载到内存，边查边写 Excel
3. **连接池**：数据库连接复用，避免频繁建连接

实测：
- 10 万行：30 秒内出结果
- 100 万行：5-10 分钟
- 1000 万行：建议直接用我们的「自动导出」+「邮件通知」，后台跑

如果是金融级别的实时大屏，这个工具不太合适——它主打的是"提数 + 导出"，不是实时分析。
```
