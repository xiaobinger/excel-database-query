## 调用方IP修复 + 展开对话卡片化

### IP 修复
- 现象：用户报告 caller_ip 记录到的是 MAC 或 IPv6 形式。原因：原 `get_client_ip()` 只读 `X-Forwarded-For` 头，docker 部署的 `nginx/nginx.conf` 中 `/v1/` 路径没设 `X-Real-IP`/`X-Forwarded-For`，回落到 `request.remote_addr`（gunicorn 监听 IPv6 时常见 IPv4-mapped IPv6 或链路本地地址）。
- `app/services/open_api_service.py`：
  - 新增 `_normalize_ip()`：剥 `::ffff:1.2.3.4` → `1.2.3.4`、剥 `1.2.3.4:port`、过滤链路本地/loopback、非合法IP（MAC `aa:bb:cc:..`）返回空。
  - `get_client_ip()` 改为按 `X-Forwarded-For`（多级链式取首）> `X-Real-IP` > `remote_addr` 顺序取首个合法IP。
- `nginx/nginx.conf`：给 `/v1/` 路径补 `X-Real-IP $remote_addr` + `X-Forwarded-For $proxy_add_x_forwarded_for` 头与SSE缓冲配置（之前只 `/api/` 路径有，缺 `/v1/`）。

### 展开对话列表卡片化
- 旧：el-table 紧凑表（白底细线）；新：垂直卡片列表（Linear/Notion风格）。
- 卡片结构：左侧 4px 状态色条（成功绿/失败红），右侧 body。
  - header 行：时间+时钟图标、端点tag、会话ID、状态tag、详情/删除按钮（右侧）。
  - 中段：用户本次指令摘要（2行省略），后端 `/logs` 与详情接口新增 `preview` 字段（`_extract_user_preview` 提取首条user消息，截断120字+…，>200KB对话走正则子串避免阻塞）。
  - 底行：模型/Token/耗时/IP chips，hover 浮窗显示完整数据。
- 整卡 hover 边框高亮+阴影，点击进入详情；删除按钮 @click.stop 隔离。
- 用户体验：失败卡片整体淡红底（`.call-card.is-failed { background: #fef8f8 }`），一眼识别。
- 测试覆盖：IP 解析（IPv4/映射IPv6/带端口/loopback/链路本地/MAC/正常IPv6）、preview 提取（首条user、空、损坏JSON回退、大体量、截断、转义字符）。
